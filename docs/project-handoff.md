# 项目讨论记录

**整理日期**　2026-11-23。本文为本次聊天的决策摘要。

## 用户提出的目标

1. 整理昇腾平台的 EP 优化方案，先调研可复用的开源实现与 benchmark。
2. 构建测试框架，调用昇腾 EP 融合算子，维护基于 PyTorch 的多流方案，接入 MoonEP、UltraEP 等负载均衡方案。
3. 覆盖典型模型，比较性能和资源占用，尤其关注显存。提供各方案接入实际模型的指导。
4. 当前没有 NPU 环境，先检视实施计划，再生成可以验证的代码。

## 已完成

- [开源调研](ascendep-open-source-survey.md) 汇总了 DeepEP-Ascend、SGLang、CANN、MindSpeed/FSDPTurbo、MoonEP 等实现与测试入口，区分设备实测、社区适配和算法参考。
- [v0.1 计划](ascendep-v0.1-plan.md) 给出 CPU 单进程参考、两进程 EP、模型接入示例以及后续 NPU 验收的顺序。

## 讨论形成的设计建议，待评审

- 以逻辑专家 ID 和路由权重定义模型语义，物理专家放置独立描述。规划、缓冲与通信高度耦合的实现允许整套接入。
- 同一份实现供 benchmark 和模型示例调用。用同一组权重、输入和路由回放核对输出、梯度与参数更新。
- 同时评价固定工作量下的延迟与峰值 HBM，以及固定 HBM 预算下的可持续吞吐。CPU 阶段验证训练语义，实际异步重叠和 HBM 在 NPU 上采集。

## 延续工作的位置

当前待评审事项是首批模型场景、CPU 回归边界，以及固定冗余副本是否纳入 M3。拟定 M1 的起点为小尺寸 SwiGLU MoE 和确定性 Top-k 加权归并测试。项目尚未实现运行时或执行性能测试。
