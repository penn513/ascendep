# CPU 首版检视记录

本次交付对应当前无 NPU 环境下的 CPU 实现与验证；完整设备评测仍按 v0.1 计划推进。

已完成的检视和修正：

| 问题 | 修正与证据 |
|---|---|
| 空 receiver 或上游 hidden 不求梯度时，部分 rank 可能不进入反向通信 | 保证交换张量进入反向图；真实两进程覆盖无上游梯度、空源 rank、单 rank 接收热点。 |
| 可变 split 的逆交换、重复 token 的专家梯度容易错位 | 反向显式交换 send/recv split；独立逻辑专家参考验证输出、dX、dTopKWeight、专家梯度和更新后权重。 |
| 副本本地更新或刷新遗漏会破坏持续训练 | optimizer 仅持有 owner 参数；副本梯度归还后统一更新，再广播刷新；同一 trace 的关闭/固定副本开启及热点迁移连续两步通过。 |
| 使用第二次排序计算逆置换有不必要开销 | 用一次 scatter 构造逆置换，保留目的 rank 的稳定排序；训练回归检查顺序和梯度。 |
| 全量随机采样可能申请 tokens × E 工作区 | 使用 1024-token 分块；大配置流式审计只保留 chunk 与计数，不创建专家参数。 |
| 低倾斜目标可能低于小样本随机噪声 | 保留最佳候选并记录实际误差；未达容差不标记 matched，benchmark 拒绝该随机场景。 |
| 总耗时或资源空缺可能被报告掩盖 | 完整前反向独立计时，逐迭代先取最慢 rank；保留原始时间、990 个 not_run 设备配置及 HBM 空值原因。 |
| macOS 默认 rendezvous 启动失败 | 本地 launcher 使用显式 loopback、legacy TCPStore，并限制进程生命周期；实际两进程回归与训练示例运行成功。 |

当前验证为 FP64、无动量/无 weight decay 的 SGD。测试不证明高阶梯度、其他优化器、真实 MoonEP/UltraEP 策略、NPU 多流、任何原生设备后端或 EP8–256 通信已可用。EP8–256 当前只完成逻辑路由检查及矩阵登记。

测试结果和逐场景误差由 `python -m ascendep regress` 写入 `reports/regression/`，避免将机器相关时间写成通用性能结论。CPU 参数与冗余权重字节数为精确张量计数；进程 RSS 为峰值，激活与通信缓冲峰值尚未插桩。源码版本盘点、设备阶段打点与曲线、native 策略接入和完整训练框架接入仍为后续任务。
