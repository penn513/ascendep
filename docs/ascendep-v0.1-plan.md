# ascendep v0.1 实施与验收计划

**状态**　按 2026-11-23 最新评审意见修订；用户随后要求生成代码并检视优化，已开展 CPU 首版实施。下文保留完整目标与验收条件；实际已执行范围及限制见 README 和 `reports/regression/`，不将计划清单视为已完成适配。

**首版目标**　在普通 CPU 机器上，用同一份模型权重、输入和逻辑路由，验证专家并行 MoE 的前向、反向和一步参数更新。让同一实现既能由 benchmark 驱动，也能作为 PyTorch 模型的一层调用。首版产出可复现的正确性报告与接入示例，后续沿用这些用例评测昇腾融合算子、多流和动态专家方案。

**设备评测必选范围**　每种 EP 实现均独立切换负载均衡优化。每种开关状态均覆盖均衡路由和多档不均衡路由，EP 规模为 **8/16/32/64/128/256**。非融合实现包含 Megatron、MindSpeed、FSDPTurbo 的不同实现；融合及整体优化实现包含 lueelu/DeepEP PR #10 对应代码中的 MegaMoE、DeepEP、ep_gmm_fused，DeepSeek DeepEP-Ascend，CANN ops 的 DeepEP、MegaMoE、MC2，以及 MoonEP。每项结果必须分别报告前向、完整反向和前反向总耗时。CPU 阶段完成路由构造、矩阵枚举和训练语义验证；完整规模的 NPU 性能验收在设备阶段完成。

## 一、实施顺序与验收

| 阶段 | 代码与交付物 | 验收条件 |
|---|---|---|
| M1　单进程参考与路由生成 | 一个朴素的 PyTorch MoE 参考层。按逻辑专家执行 SwiGLU，按 top-k 权重归并。提供微型配置、确定性输入、均衡及多档不均衡路由生成与回放。 | 小尺寸手算用例校验加权归并；相同 trace 可重复得到相同输入和输出。验证路由唯一性、计数守恒、目标与实际 MaxVio；更改一个路由或权重后，测试能识别差异。 |
| M2　真实 CPU 多进程 EP | torchrun + Gloo，先支持 2 rank。每 rank 仅持有本地专家，执行 token 排序、按目的 rank 交换、专家计算、回传和加权归并。实现可反传的数据交换，反向交换恢复原始 split 与顺序。 | 同一全局 batch、初始化及损失归一化下，与 M1 对齐输出、输入梯度、专家参数梯度、top-k 权重梯度，以及一次 SGD 更新后的逻辑专家权重。覆盖非均匀 split、零收发 peer、空专家和单 rank 接收热点。 |
| M3　场景、报告与接入 | 提供 CLI、实现注册表、能力清单、完整测试矩阵、JSON 明细、Markdown 对比表和一个最小训练示例。benchmark 与示例导入同一 MoE 实现。执行一个固定冗余副本案例，验证物理专家映射、梯度归还及更新后副本刷新。 | 一条命令完成 CPU 回归；枚举所有实现 × 六档 EP × 五档路由 × 负载均衡策略配置，缺失项保留状态和原因；报告包含独立前向、反向、总耗时字段。同一 trace 可重放到不同物理放置；冗余专家连续两步与参考一致。缺少可选后端时 CPU 路径正常。 |
| M4a　非融合 NPU 基线 | 先运行 PyTorch/HCCL 单流基线，再接入 Megatron、MindSpeed、FSDPTurbo 的非融合单流、多流及其他实际存在的独立实现，按配置分别注册。 | 每项先通过训练数值验证，再覆盖 EP8/16/32/64/128/256 的均衡和多档不均衡路由，采集前向、完整反向、总耗时和峰值 HBM。框架原生实现与新增昇腾适配分开标识。 |
| M4b　融合与整体方案 | 接入第二节全部必选实现，包括各来源的 DeepEP、MegaMoE、ep_gmm_fused、MC2 和 MoonEP；按原生前反向能力补齐整层训练封装。 | 使用与 M4a 相同的输入、权重、逻辑路由和梯度条件完成相同矩阵。通信微基准单列，整层结果包含专家计算。缺少反向或不支持规模的项仍列出缺口，不能以仅有前向作为该训练项完成。 |
| M4c　全矩阵汇总与模型接入 | 汇总全部实现的覆盖率、均衡及不均衡性能曲线、EP 扩展性和显存，选择一个实际训练框架入口验证接入。 | 所有必选组合均有结果或明确缺口；训练完成项必须前向、反向及更新正确性通过且有设备实测。未实现、未运行、失败和不支持项分别列示，未满足项保留后续适配任务。 |

M1–M3 是第一批 CPU 代码范围，M4a–M4c 是完整设备评测范围，不再以“接入一个多流、一个融合路径”作为项目范围。此前环境检查记录为两个本地 Python 环境均未发现 PyTorch 和 pytest；编码阶段重新探测并准备 CPU 测试环境，运行两进程 Gloo 探针，确认可变 split 和零 split 等目标用例。CPU 两进程测试不等于通过 EP8–256 实测；环境依赖受限时逐项列明已运行和未运行的测试。

**接入登记要求**：每个独立实现/变体记录 repo、commit、PR head SHA（若适用）、入口、框架开关、依赖版本、NPU 型号、拓扑限制、EP 范围、dtype、形状、前向/反向/路由权重梯度能力、实际融合范围和训练封装方式。同名 DeepEP/MegaMoE 必须按来源区分。框架调用同一 CANN 内核时增加 `kernel_family`，既保留框架入口对比，也标明底层实现复用。

PR #10 的正文已提供 BF16 训练接口及 EP8/16/32 的作者前反向验证说明；本项目不将其等同于独立实测或 EP64/128/256 支持证明。接入时固定实际 head commit，分别核验三个路径，不能直接用默认分支代替该 PR 的代码。

## 三、实现边界

- **模型侧入口**：模型传入本 rank 的 hidden states、逻辑 top-k expert IDs 和可求导的 top-k 权重，接收与输入 token 顺序一致的输出。首版从 router 输出开始验证，专家参数归属和进程组可由调用者指定。
- **执行与放置**：简单策略提供逻辑专家到物理副本的映射。带预取、专有缓冲或梯度归还的实现可以整体接入。首版只为实际用例抽取接口。CPU 固定副本测试仅代表冗余训练语义通过。
- **多流验证**：CPU 阶段用串行执行校验分块、归并及依赖关系；NPU 阶段用真实流和事件检查缓冲复用、异步读写正确性，并测量重叠和关键路径。
- **接入指导**：首版提供独立 PyTorch 模型替换示例，标明输入布局、参数所有者、梯度归约和 optimizer 调用位置。设备阶段提取并调用各框架原生 MoE 路径；确实无法独立调用的，在原框架最小训练驱动中测量，并标明额外执行范围。M4c 再选择一个完整模型训练入口验证。

## 四、路由场景与测试矩阵

### 4.1 两类必选路由

| 路由类别 | 默认配置 | 构造与验收 |
|---|---|---|
| 均衡 | `balanced`，目标 expert MaxVio=0 | 使用确定性轮转/配额构造，将全局 Top-k 路由尽量平均分配到逻辑专家；在整除配置下专家计数完全一致，同时检查固定均匀放置下的 rank 负载。非整除时专家计数至多差 1，记录实际值，不用独立均匀随机抽样代替均衡。 |
| 不均衡 | `skewed`，目标 expert MaxVio 为 **0.2/1/10/20**，支持自定义列表 | 参考 MoonEP 的 lognormal 专家热度和不放回 Top-k 抽样，再搜索 sigma 逼近各档目标；输出目标、实际值、误差和可达性状态。默认四档与 MoonEP 横评脚本的目标列表对齐。 |

参考源码：[路由生成器](https://github.com/MoonshotAI/MoonEP/blob/master/tests/generate_topk_routing.py)、[不均衡度扫描与 sigma 搜索](https://github.com/MoonshotAI/MoonEP/blob/master/benchmarks/bench_vs_deepep.py)。这些是路由方法参考；本项目的训练计时边界见第六节。

构造方法：为每个逻辑专家生成共享随机量 `z_e ~ Normal(0,1)`，热度 `p_e ∝ exp(sigma × z_e)`；各源 rank 对每个 token 按该热度不放回抽取 K 个专家。共享热度种子保证各 rank 的热门专家一致，源 rank 的独立种子控制 token 抽样。sigma=0 的均衡场景使用确定性构造；sigma>0 的随机场景单独记录抽样噪声。路由权重使用统一、可求导且可回放的生成规则，各后端消费同一份权重，不随物理调度变化。

令 `T_global` 为 EP 组全局输入 token 数，`K` 为 Top-k，`E` 为逻辑专家总数，`n_e` 为全局路由到专家 e 的条目数：

- `sum(n_e) = T_global × K`；同一 token 的 K 个 expert ID 必须互异、合法，禁止靠丢 token 或重复专家制造负载。
- `expert MaxVio = max(n_e) / (T_global × K / E) - 1`；例如 0.2 表示最忙专家为平均值的 1.2 倍，1 表示 2 倍。
- Top-k 不放回条件下 `expert MaxVio ≤ E/K - 1`，且计数离散、低不均衡档存在抽样噪声。搜索保留最接近候选，建议容差 `max(0.02 × target, 0.005)`；不可达或未达到容差时明确标识，不改写为目标已达成。
- 同时记录专家负载 CV、固定放置下 rank 最大/平均负载比及实际调度后 rank 最大/平均计算负载比。逻辑路由的不均衡度与动态冗余后的物理负载分开统计。

trace 在计时外生成一次并冻结，保存 expert IDs、路由权重、输入种子/生成器版本或输入张量、源 rank 和 token 顺序及内容哈希。CPU/NPU 随机序列不要求天然一致，跨实现以同一 trace 为准。固定热点为必选，热点迁移为补充序列，用于检验动态 planner 的持续收益、梯度归还及更新后副本一致性。

相同 expert MaxVio 可能对应不同 rank 倾斜。除共享热度的随机场景外，补充“热专家集中于少数 rank”和“热专家分散于多个 rank”的固定放置案例，分别记录逻辑路由与物理放置，避免只凭专家 MaxVio 解释最慢 rank。

### 4.2 EP 规模与公平比较

- 必选规模固定为 **EP8、EP16、EP32、EP64、EP128、EP256**；EP512 及以上为后续扩展，不替代六档必选规模。
- 主矩阵为 `实现/变体 × EP{8,16,32,64,128,256} × 路由{均衡, MaxVio 0.2,1,10,20} × 负载均衡策略{关闭, MoonEP冗余专家, UltraEP冗余专家} × 模型形状 × 精度/保存模式 × 拓扑`。每种实现、每个固定形状、精度、保存模式和拓扑枚举 **30 组对照、90 个配置**（30 个关闭基线，30 个 MoonEP 开启，30 个 UltraEP 开启），每场景含前向、反向及总耗时。
- 同一横向对比固定 E、K、hidden、FFN、tokens/rank、权重、输入、路由、精度和拓扑；E 应能被六档 EP 整除，例如公共场景选 E256 或 E2048，且 K≤E。不支持公共形状的实现保留不支持记录，不暗中更改 E 或 K。
- 主扫描固定 tokens/rank（默认 4096，可配置），EP 改变时全局 batch 随之变化，属于固定每卡输入的扩展性测量；另设固定全局 tokens 的扫描时单独标识，不能混用速度提升口径。
- 同一 EP 的不同实现使用完全一致的 trace；不同 EP 的 trace 按配置生成并匹配目标不均衡度。每个 EP 记录实际 MaxVio，不能因采用相同 sigma 就宣称负载倾斜相同。
- 同一 EP 能在超节点内/跨超运行时分别测量，记录实际 rank→设备→超节点映射和通信网层。变更物理放置时保持逻辑路由固定。
- 对开启策略的方案记录冗余预算和额外显存；同时评价固定 tokens/rank 和固定 HBM 预算，不能通过增加副本而省略资源代价。

### 4.3 同一路由下的负载均衡开关对照

| 策略配置 | 执行条件 | 对照方式 |
|---|---|---|
| 关闭 | 每个逻辑专家固定在原始 owner 上执行，关闭负载均衡 planner、冗余副本和相关搬运。保留该 EP 实现自身的通信、融合和流配置。 | 同一组内共享一次关闭基线。 |
| 开启 MoonEP 冗余专家 | 使用 MoonEP 策略选择物理副本，记录实际专家放置、权重预取和梯度归还。 | 与本组关闭基线配对。 |
| 开启 UltraEP 冗余专家 | 使用 UltraEP 策略分配冗余专家，记录实际执行入口、放置和副本维护开销。 | 与同一关闭基线配对，两种开启策略使用相同副本预算。 |

每组固定执行后端及融合开关、EP 大小、拓扑、模型权重、源 token、逻辑 Top-k ID 和路由权重。开启策略只能改变物理副本选择和任务分配。均衡路由也执行全部策略，以测出 planner 和副本维护本身的代价。M3 用同一 trace 核对开关两侧的输出、梯度和两步参数更新，M4 在非融合及融合路径执行全部配对。

报告并列展示每组关闭、MoonEP 开启、UltraEP 开启的前向、完整反向、总耗时、训练步耗时（含副本刷新）、峰值 HBM 和调度后 rank 最大/平均负载。对每种开启策略，用配对的关闭耗时除以开启耗时计算加速比，并报告开启减关闭的峰值 HBM 差值。物理副本数、实际迁移字节数随结果保存。

兼容性按“执行后端 × 策略”验证。策略与通信内核强绑定时，保留原生整套测点并注明绑定关系。同一执行后端无法关闭冗余或接入指定策略时，将对应配置标为待适配或不支持，填写原因，配对收益留空。跨后端比较可用于整套方案评估，不能据此归因负载均衡收益。

### 4.4 首批模型形状

| 场景 | 配置与用途 |
|---|---|
| CPU 可执行小形状 | 建议 2 rank、4 个逻辑专家、Top-1/2、hidden 16、FFN 32，覆盖均衡、可达的不均衡档、单热点、热点迁移。小 E/K 下不可达的 MaxVio10/20 用于验证配置拒绝；另用 E256 的路由统计验证默认四档。为非对称 split、零流量 peer、同一 token 多个专家落在同一 rank 准备显式输入。 |
| DeepSeek 型常规 MoE | 保存 hidden、实际通信维度、专家 FFN、共享专家与精度配置。首版以缩小形状验证所实现的 routed-expert 路径；报告注明共享专家是否计入。 |
| Kimi 型 latent MoE | 分开记录模型 hidden 和参与 EP 交换的 latent 维度，并明确投影与通信的先后位置。提供小形状投影实例，验证输出形状与梯度。 |
| 大 EP 配置检查 | 录入 E2048、Top-16、专家 FFN 4096、每 rank 4096 tokens 的候选场景。CPU 分块/流式验证六档 EP 的配置、路由合法性及统计，不实例化完整专家权重；NPU 按显存预算运行可容纳的形状，OOM 项如实登记，大模型形状不支持时不冒充完成该项。 |

回放文件按 step、microbatch、层和源 rank 保存逻辑路由、权重及 token 顺序，另记物理拓扑和放置。可复现的合成输入保留种子与生成器版本。真实模型 trace 可在后续使用同一格式接入。

## 五、正确性与资源口径

1. **独立参考与误差**。参考层直接按逻辑专家选择 token，独立于分布式实现的排序、逆置换和副本映射。小形状 CPU 默认 FP64，对齐使用绝对与相对容差并记录最大误差。校验空专家时统一处理未参与计算的梯度和零梯度语义。
2. **跨 rank 对齐**。按全局 token 顺序还原输出和输入梯度，按逻辑 expert ID 对齐参数梯度；单独检查每条有效 top-k 路由恰好完成一次、每个副本梯度恰好归还一次。固定全局损失定义，避免误把 rank 平均差异计为 EP 误差。
3. **训练覆盖**。每种实现都验证输出、输入梯度、路由权重梯度、专家各矩阵梯度及参数更新；包含非均匀 split、空专家、零收发 peer、单 rank 热点。动态副本还需跨两个优化步检查梯度归还、逻辑专家更新与副本刷新。每档路由先过正确性，再采性能。
4. **资源**。CPU 表分别记录权重、缓冲等张量的理论字节数；进程 RSS 若可得则单列。NPU 表记录各 rank 峰值 allocated/reserved、设备侧可获得的占用及采集范围，汇总最重 rank，并注明 SHMEM/HCCL 等外部分配的可见性。不可采项使用空值及原因。
5. **比较条件**。报告关联模型配置、trace ID、精度、EP、rank 映射、软件版本及计时边界。先在固定 tokens/rank 下比较时间与资源，再在给定 HBM 预算下扫描最高可持续吞吐。CPU 耗时仅用于本地回归，NPU 性能与显存需实机填入。

## 六、前向、反向及性能报告

### 6.1 统一训练计时边界

| 指标 | 必须包含的执行范围 |
|---|---|
| `fwd_ms` | 从消费模型输入及逻辑路由开始，经在线 planner、必要权重预取、token 重排、dispatch、专家 GMM1/SwiGLU/GMM2、combine、乘权归并，到源 token 顺序的输出可被下游消费；实际融合的步骤只计一次。 |
| `bwd_ms` | 使用该次前向上下文，从给定同一 `grad_output` 开始，到输入梯度、Top-k 权重梯度和所有专家参数梯度完成且可消费，含反向通信、必要重计算及冗余专家梯度归还。 |
| `fwd_bwd_ms` | 独立采集完整前向+反向迭代的关键路径；不包含外部损失计算与 optimizer 更新。每次迭代取最慢 rank 后统计，不能用前向和反向各自 P50 相加代替。 |
| `train_step_ms`（补充） | 前向、损失、反向、optimizer 更新及必要副本刷新；单列刷新时间，验证持续训练代价。 |

前向与反向均处于训练模式，不能用推理前向充当训练前向。显式给定公共输出梯度，控制梯度累积/清零方式、缓存、激活保存和重计算策略。固定 trace 的构造、一次性编译、初始权重装载和缓冲初始化放在预热/准备阶段；运行时根据当前路由执行的 planner/预取必须计入。如果复用 plan，单列 `cached_plan` 结果及构建/刷新代价，开启策略时默认测在线 plan。

设备计时需覆盖全部参与流并在消费者就绪处结束；同时记录主机端到端墙钟，避免遗漏 host planner。默认预热 20 次、采样 50 次，允许配置并在报告中记录。对 `fwd`、`bwd`、`fwd_bwd` 分别逐迭代取各 rank 最大耗时，再统计 P50/P95。记录逐 rank 原始数据，保留原生算子计时作为补充。

dispatch/combine 库必须与公共专家计算组合成完整 MoE 训练路径后，才能进入整层对比。只有原生前向的实现需要适配并验证反向；若使用其他实现的反向，则独立命名为混合配置，明确 `forward_backend` 与 `backward_backend`。尚未补齐时 `bwd_ms=null`、状态为缺少反向，该项训练验收未完成。不能填 0、按前向倍数估算反向，或静默切换后端。

阶段打点包括 planner、预取、重排、通信、GMM、激活、梯度归还、刷新；融合算子无法拆分的填空值并解释。重叠阶段不直接相加推导总耗时。另附纯通信微基准，明确它不包含完整专家前反向。

### 6.2 结果字段与展示

主表一行对应一个实现/变体、EP、路由、负载均衡开关和策略、模型、精度/保存模式、拓扑组合，至少包含：

| 字段组 | 内容 |
|---|---|
| 身份与配置 | `backend_id`、variant、repo/commit/PR SHA、实际前反向后端、kernel_family、EP、模型形状、dtype、精度/激活保存/重计算、拓扑、负载均衡策略、开关、配对基线 ID、冗余预算、trace ID/hash。 |
| 路由与负载 | balanced/skewed、target/actual MaxVio、sigma、种子、CV、调度前/后 rank 最大/平均负载比、可达性及误差。 |
| 正确性 | 输出、dX、dTopKWeight、专家参数梯度、更新后权重误差及容差、通过/失败状态。 |
| 性能 | 前向、完整反向、前反向总耗时各自 P50/P95；训练吞吐 `T_global / (fwd_bwd_ms/1000)`，单位为源 tokens/s；原始 token 数不乘 Top-k。可补充训练 step 吞吐。 |
| 资源与覆盖 | 各 rank 峰值 HBM 及最重 rank、SHMEM/通信缓冲、冗余权重、保存激活、额外工作区、外部分配可见性；pass/failed/not_run/unsupported/missing_backward/OOM/timeout 与原因。 |

同时输出 JSON 明细、逐迭代/逐 rank 原始记录、Markdown 对比表，以及按 EP 和实际不均衡度绘制的前向、反向、总耗时/吞吐和峰值 HBM 曲线。所有未执行/不支持项保留在矩阵中，缺少数值使用空值；报告给出完成数/计划数，不能只展示成功场景。

## 七、拟交付的代码入口

- `ascendep/`：路由生成与回放、参考 MoE、分布式 EP、放置策略、后端适配器/能力注册表、矩阵调度、评测与报告。可选 NPU 依赖按需加载。
- `configs/`：小形状配置、模型场景、六档 EP、均衡/多档不均衡、后端变体和拓扑；每份配置标明已验证范围。
- `tests/`：路由目标与计数、默认矩阵完整性、报告缺失状态、单进程参考、真实两进程训练对齐和固定冗余副本回归；NPU 测试单独标记。
- `examples/`：可运行的 PyTorch 训练与替换示例。README 记录 CPU 安装方式、运行命令、报告解释和后端能力表。

**CPU 首版完成条件**　在干净的 CPU 环境按 README 跑通参考与两进程对齐测试；均衡和多档不均衡路由可生成、统计和回放；完整必选矩阵可枚举，所有结果有前向、反向、总耗时字段与状态；用同一配置运行示例和 benchmark。CPU 通过不代表任何 NPU 后端已支持。

**设备阶段完成条件**　第二节必选实现及实际变体，完成六档 EP、均衡和多档不均衡、各负载均衡策略开关组合的前反向正确性、独立计时及资源采集。受平台/实现限制的组合必须列出证据和适配缺口，矩阵有记录不等于该项通过；这些缺口持续保留为未完成任务。950DT 性能排名与 HBM 对比以 M4 实测为准。
